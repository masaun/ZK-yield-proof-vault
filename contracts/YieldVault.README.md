# YieldVault Contract

A yield-bearing vault that uses Zero-Knowledge proofs to verify yield calculations on Mantle EVM.

## Overview

The YieldVault contract implements a complete flow for:
- User deposits
- Epoch management and snapshots
- ZK proof verification via YieldProofVerifier
- Secure yield claiming/minting

## Architecture

```
Users
  │
  │ (deposit)
  ▼
YieldVault Contract (Mantle EVM)
  │
  │ (epoch snapshot)
  ▼
Off-chain Prover (ZK Engine - Noir Circuit)
  │
  │ generates zk-proof
  ▼
YieldProofVerifier Contract (Mantle)
  │
  │ verifies proof
  ▼
Yield Claim / Mint
```

## Key Features

### 1. **Deposit Management**
- Users can deposit ETH into the vault
- Balances are tracked per user
- Total deposits are recorded for epoch snapshots

### 2. **Epoch System**
- Epochs track time periods (by block numbers)
- Each epoch stores:
  - Start and end blocks
  - Total deposits at snapshot time
  - Total yield for the epoch
  - Merkle root of all user balances
  - Snapshot status

### 3. **ZK Proof Verification**
- Integrates with `YieldProofVerifier.sol`
- Verifies proofs generated by Noir circuit
- Ensures yield calculations are correct and private

### 4. **Yield Claiming**
- Users claim yield by submitting a ZK proof
- Proof demonstrates:
  - User's balance in the Merkle tree
  - Correct yield calculation
  - KYC eligibility (optional)
  - Valid nullifier to prevent double-claiming
- Upon verification, yield is transferred to the user

### 5. **Security Features**
- Nullifier system prevents double-claiming
- Public inputs validation ensures epoch integrity
- Owner-only admin functions
- Custom errors for gas efficiency

## Smart Contract Functions

#### `deposit()`
```solidity

```
Deposit ETH into the vault.

#### `claimYield(uint256 epochId, bytes calldata proof, bytes32[] calldata publicInputs)`
```solidity
function claimYield(uint256 epochId, bytes calldata proof, bytes32[] calldata publicInputs) external
```
Claim yield for a specific epoch using a ZK proof.

**Public Inputs Order:**
- `[0]` expected_latest_user_balance_root (bytes32)
- `[1]` latest_block_number (uint64)
- `[2]` yield_rate (uint64)
- `[3]` epoch_start (uint64)
- `[4]` epoch_end (uint64)
- `[5]` latest_total_yield (uint64)
- `[6]` expected_nullifier (bytes32)

## Deployment

### Prerequisites
- Foundry installed
- Deployed `YieldProofVerifier` contract

### Deploy Script

```bash
cd contracts

# Build
forge build

# Deploy
forge create --rpc-url <MANTLE_RPC_URL> \
  --private-key <PRIVATE_KEY> \
  src/YieldVault.sol:YieldVault \
  --constructor-args <VERIFIER_ADDRESS> <INITIAL_YIELD_RATE>
```

### Example Constructor Arguments
- `VERIFIER_ADDRESS`: Address of the deployed YieldProofVerifier contract
- `INITIAL_YIELD_RATE`: Initial yield rate (e.g., `1000000000000000` for 0.001 per block)

## Usage Flow

### 1. User Deposits
```solidity
// User deposits 10 ETH
yieldVault.deposit{value: 10 ether}();
```

### 2. Admin Creates Epoch Snapshot
```solidity
// After some time, owner snapshots the epoch
bytes32 balanceRoot = computeBalanceRoot(); // Off-chain computation
uint64 totalYield = calculateTotalYield(); // Off-chain computation

yieldVault.snapshotEpoch(balanceRoot, totalYield);
```

### 3. User Generates Proof Off-Chain
Using the Noir circuit in `circuits/`:
```bash
cd circuits
nargo prove
```

### 4. User Claims Yield
```solidity
// User submits proof and public inputs
bytes memory proof = loadProofFromFile();
bytes32[] memory publicInputs = preparePublicInputs();

yieldVault.claimYield(epochId, proof, publicInputs);
```

## Public Inputs Structure

The public inputs must match the circuit's requirements:

| Index | Name | Type | Description |
|-------|------|------|-------------|
| 0 | expected_latest_user_balance_root | Field | Merkle root of user balances |
| 1 | latest_block_number | u64 | Current block number |
| 2 | yield_rate | u64 | Yield rate per block |
| 3 | epoch_start | u64 | Epoch start block |
| 4 | epoch_end | u64 | Epoch end block |
| 5 | latest_total_yield | u64 | Total yield for epoch |
| 6 | expected_nullifier | Field | Unique nullifier |

## Security Considerations

1. **Nullifier System**: Prevents double-claiming of yields
2. **Public Input Validation**: Ensures proof matches epoch data
3. **Access Control**: Owner-only admin functions
4. **Reentrancy Protection**: Uses checks-effects-interactions pattern
5. **Custom Errors**: Gas-efficient error handling
